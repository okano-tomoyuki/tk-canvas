# 0011. 生成するクラスはルートのクラスを継承する（is-A）

- 状態: 承認
- 日付: 2026-09-25

## 背景

当初の生成コードでは、生成するクラスがルートのウィンドウ（`tk.Tk` / `tk.Toplevel`）を**メンバとして持っていた**（has-A）。

```cpp
class MainWindow { cpp_tk::Tk main_window; ... };
```

この構成には次の不便があった。

1. cpp_tk では、すべての Widget が `post()`（別スレッドから GUI の操作を依頼する、スレッドセーフな唯一の手段）を持つ。
   しかし has-A では、生成したクラスそのものは Widget ではない。利用側は内部のメンバを経由する必要があり、
   「画面のオブジェクトに post する」という自然な書き方ができない。
2. ルートがウィンドウに限られるため、他の画面に埋め込む部品（Frame）をデザインできない。

## 検討した選択肢

- **has-A のまま（現状）**: 生成コードの構造が単純。ただし上の不便は残る。
- **is-A（ルートのクラスを継承する）**: 生成したクラス自身が Widget になり、`post()` などをそのまま使える。
  ルートのクラスを選べるようにすれば、部品（Frame）も同じ仕組みで作れる。
  一方で、ウィジェット・変数・ハンドラの名前が基底クラスのメンバと衝突しうる（例: `title`、`destroy`）。

## 決定

**生成するクラスは、DSL のルートのクラスを継承する。**

1. ルートにできるクラスは `tk.Tk`、`tk.Toplevel`、`ttk.Frame`、`tk.Frame`、`ttk.Labelframe`、`tk.LabelFrame` とする。
   Notebook・PanedWindow は対象外とする。
2. `window`（wm 系の設定）は `tk.Tk` / `tk.Toplevel` のときだけ書ける。
3. ルートの `options` は、基底クラスの生成後に `configure`（Python）/ `config`（C++）で設定する。
   生成時にしか指定できないオプション（`class` など）は生成コードに反映せず、警告する。
   必要なら利用者がコンストラクタ引数（Python の `**kwargs`、C++ の `options`）で渡す。
4. ルートの `id` はデザイナー上でルートを指す名前として残す。生成コードのメンバにはならない。
5. ウィジェット・変数・ハンドラには、基底クラスのメンバと同じ名前を使えない（検証エラー `reserved-name`）。
   ルートのクラスを後から変えても問題が起きないよう、ルートにできるすべてのクラスのメンバ（tkinter と cpp_tk の両方）をまとめて予約する。
6. 既存の生成済みファイルの基底クラスが DSL のルートのクラスと違う場合（ルートのクラスを変えた場合）は、
   **何も書き込まずにエラーにする**。基底クラスが変わると区間の外（クラスの宣言・コンストラクタ）も変わるため、利用者に直してもらう。
   ただし `tk.Frame` → `ttk.Frame` のような変更は実際に起こりうるため、**この扱いは今後の要件によって変わる可能性がある**
   （例: 区間の外の決まった箇所だけを自動で書き換える）。
7. 新しい画面は、ルートのクラスを選んで作る（コマンド「Tk Designer: 新しい画面を作成」）。

コード生成の画面（生成する言語・クラス名・出力先の指定）も同時に見直した。
「コード生成…」ボタンで設定の画面に切り替わり、指定は DSL の `codegen` に保存されるため、いつでも言語を選び直せる（ADR 0010 の決定の範囲内）。

## 影響

- 生成コードの形が変わる（codegen-design.md §3）。以前の形で生成したファイルはマーカー区間の外（クラスの宣言・コンストラクタ・`run()`）が
  新しい形と合わないため、作り直す（ファイルを退避してから生成する）か手で直す必要がある。
  以前の形のファイルは基底クラスがないため自動では検出できない（基底クラスの照合は既知の基底クラスが書かれている場合だけ行う）。
- `run()` は生成しない。基底クラスの `mainloop()` を使う。
- DSL の形式（formatVersion 1）は変わらない。ルートに書けるクラスが増え、名前の制限（`reserved-name`）と `window` の制限（`window-not-allowed`）が加わる。
  既存の DSL で基底クラスのメンバと同じ名前を使っている場合は、検証エラーになるので改名する。
- キャンバスでは、Frame のルートをタイトルバーなしで要求サイズのまま表示し、周りにドロップできる余白をとる。
  今後、表示の拡大率（ズーム）を導入する予定（layout.md §5）。
