# ビジョン

## 目的

C++ 向け Tcl/Tk ラッパーライブラリ [cpp_tk](https://github.com/okano-tomoyuki/cpp_tk) および Python tkinter の利用を促進するため、
保守性と利便性を兼ね備えた GUI デザイナーを提供する。

## 想定ユーザーと利用シーン

- 社内ツール・プロトタイプ・学習用途の GUI を手早く作りたい **C++ 開発者**（cpp_tk 利用者）
- 同様の用途で tkinter を使う **Python 開発者**
- Qt / wxWidgets ほどの機能は不要で、依存関係・ビルド・学習コストの軽さを優先する人

## 提供価値

1. **1つの DSL から cpp_tk / tkinter の両方のコードを生成できる**
   cpp_tk は tkinter と同じ概念・命名で整備されているため、同一の画面定義を両言語で再利用できる。
2. **Tk の概念に忠実**
   `pack` / `grid` / `place`、`command`、`bind`、`*Var` など、Tk の概念をそのまま扱う。
   生成コードを読んで学べること、手書きコードと混在しても違和感がないことを重視する。
3. **日常の開発フローに乗る**
   VS Code 上で編集し、DSL はテキストとして git で差分管理でき、コード生成は CLI からも実行できる（CMake 等への組み込み）。

## スコープ

### やること（初期）

- VS Code 拡張としてのビジュアルエディタ（ウィジェット配置・プロパティ編集・ツリー表示・Undo/Redo）
- DSL ファイルの定義と JSON Schema による検証
- cpp_tk (C++) / Python tkinter へのコード生成
- コード生成 CLI

### 検討中（後で判断）

- 実際の Tk（wish / tclsh）を用いた実機プレビュー
- Tcl スクリプトの生成
- Tk からのウィジェットオプション情報の自動抽出

### やらないこと

- VS Code 以外の単体アプリ化
- 既存の手書きコードからの逆変換（コード → DSL）
- 旧実装の DSL との互換性維持
