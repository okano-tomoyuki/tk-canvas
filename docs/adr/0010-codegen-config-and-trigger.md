# 0010. コード生成の設定は DSL に持ち、生成は利用者の明示的な操作で行う

- 状態: 承認
- 日付: 2026-09-25

## 背景

コード生成（ADR 0002, 0004）を実装するにあたり、次の2点を決める必要がある。

1. クラス名・出力先のファイルなど、生成の設定をどこに持つか
2. いつ生成するか（既存のファイルのマーカー区間を書き換えるため、タイミングが重要）

## 検討した選択肢

### 設定の置き場所

- **DSL ファイルに持つ**: 拡張機能と CLI（CMake からの生成）が同じ設定を使える。画面ごとに出力先を変えられる。
- **VS Code の設定（settings.json）に持つ**: DSL は画面の定義だけになるが、CLI では別途指定が必要で、設定が二重になる。

### 生成のきっかけ

- **明示的な操作**: 利用者が書き換えのタイミングを決められる。
- **保存時の自動生成**: 手間はないが、編集途中の状態で既存のファイルが書き換わる。

## 決定

1. **生成の設定は DSL の `codegen` 項目に持つ**（dsl-spec.md §3）。書き出すのは `codegen` に書いたターゲットだけとする。
   - クラス名を省略した場合は DSL のファイル名から決める（`main_window.tkui.json` → `MainWindow`）。
   - 出力先を省略した場合は DSL と同じフォルダに同じ名前で作る（`main_window.py`、`main_window.hpp` / `main_window.cpp`）。
   - パスは DSL ファイルのあるフォルダからの相対パスで書く。
2. **生成は利用者の明示的な操作で行う**。デザイナーの「コード生成」ボタン、および CLI（`tkd generate`）。
   保存時の自動生成は、必要になれば設定として後から追加する。
3. 実装は **Python（tkinter）を先に完成させる**。生成したスクリプトを実際の Python で実行して検証し、それを正として C++（cpp_tk）へ広げる。
   C++ 版は、生成したコードのビルドによる検証の仕組み（ビルドスクリプト等）とあわせて後で整備する。

## 影響

- DSL に `codegen` 項目が加わる（formatVersion は 1 のまま。省略可能な項目の追加のため）。
- cpp_tk の `ttk::Notebook` はタブの追加に `add_tab(child, label)` しかないため、ラベル以外のオプション（sticky / padding / state / underline）を
  指定する方法が課題だった。
  （2026-09-25 追記: 既存の `Notebook::tab(tab_id, options)` がウィジェットのフルネームを tab_id として受け付けるため、
  `add_tab` の後に `tab(child.full_name(), {...})` で設定できる。cpp_tk の変更は不要になった。）
