# 0007. ウィジェットカタログは Tk から自動抽出し、手書きの補足情報を重ねる

- 状態: 承認
- 日付: 2026-09-24

## 背景

ウィジェットカタログは、ウィジェットクラスごとの「持っているオプションとその型・既定値」などを定義するデータで、次の用途に使う。

- プロパティエディタの構築（どのオプションを、どの入力部品で編集させるか）
- DSL の検証（存在しないオプション、型違い、変数型の不一致）
- コード生成（生成時にしか指定できないオプションの扱い、`command` のシグネチャ）

cpp_tk はオプションを基本的に `config` で文字列キーとして設定するシンプルな設計なので、Tk 自身が持つ情報がそのまま正になる。
対象は classic / ttk 合わせて数十クラスあり、手で書いて維持するのは現実的でない。

## 検討した選択肢

- **手書き**: 型などを自由に書けるが、網羅性と Tk のバージョン追従に難がある。
- **cpp_tk のヘッダから抽出**: オプションの多くは文字列キーで渡すため、ヘッダには現れない。
- **Tk から自動抽出**: 実際に tclsh/wish で各ウィジェットを生成し、`configure` の戻り値
  （オプション名・データベース名・クラス名・既定値）を取得する。網羅的で正確。
  ただし値の型（色・フォント・列挙値の候補など）は直接は得られない。

## 決定

**Tk から自動抽出した基本情報に、手書きの補足情報（オーバーレイ）を重ねて最終的なカタログを作る。**

| 情報 | 取得方法 |
|---|---|
| クラスごとのオプション一覧・既定値 | 自動抽出（`configure`） |
| 生成時にしか指定できないオプション | 自動抽出（生成後に `configure` を試し、エラーになるものを判定） |
| 値の型（色・フォント・画像・距離・真偽など） | データベースクラス名（`Background` → 色 等）から推定し、オーバーレイで補正 |
| 列挙値の候補（`relief`, `anchor`, `orient` 等） | 自動抽出（不正な値を設定したときのエラーメッセージから得られるものは取得）＋ オーバーレイ |
| 変数参照を受け付けるオプションと変数型 | オーバーレイ |
| `command` のシグネチャ、代表的な bind シーケンス | オーバーレイ |
| プロパティエディタでの分類・表示順・よく使うオプション | オーバーレイ |

- 抽出は**開発時**に実行するスクリプト（`tools/catalog/`）で行い、生成したカタログ（JSON）をリポジトリにコミットする。
  デザイナーの利用者が Tcl/Tk をインストールしている必要はない。
- カタログには抽出元の Tk バージョンを記録する（Tk 8.6 と 9.0 の差異に備える）。

## 影響

- 開発者は、カタログを更新するときだけ Tk 入りの tclsh（MSYS2 の mingw-w64-x86_64-tk 等）が必要。
- ttk ウィジェットの見た目に関わる設定の多くはスタイル（`ttk::style`）側にあり、ウィジェットのオプションとしては抽出されない。
  スタイルの扱いは別途検討する。
