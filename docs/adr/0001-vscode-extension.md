# 0001. 製品形態として VS Code 拡張を採用する

- 状態: 承認
- 日付: 2026-09-24

## 背景

デザイナーの提供形態を決める必要がある。想定ユーザーは日常的にエディタでコードを書く C++ / Python 開発者であり、
生成したコードはそのままプロジェクトに組み込まれる。

## 検討した選択肢

- **VS Code 拡張**: ユーザーの作業環境にそのまま乗る。ファイル管理・git・保存などを VS Code に任せられる。
  一方で Webview の制約（CSP、メッセージ通信）がある。
- **単体アプリ（Tauri / Electron 等）**: UI の自由度は高いが、ファイル管理・配布・更新を自前で抱える必要がある。

## 決定

VS Code 拡張を採用する。

## 影響

- DSL ファイルの編集には **Custom Editor API** の利用を検討する（別 ADR で決定）。
  保存・未保存状態・Undo/Redo・diff を VS Code の仕組みに乗せられる見込み。
- VS Code に依存しない部分（DSL モデル・検証・コード生成）は独立したパッケージに分離し、
  CLI やテストから単体で利用できるようにする（architecture.md で具体化）。
