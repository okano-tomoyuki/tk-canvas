# 0009. DSL のスキーマは Zod で TS 側に定義し、型と JSON Schema を導出する

- 状態: 承認
- 日付: 2026-09-24

## 背景

DSL（`*.tkui.json`）には次の3つが必要になる。

- TS の型（core・codegen・webview の実装で使う）
- 実行時の検証（ユーザーが手で編集するファイルを読み込むため）
- JSON Schema（テキストエディタで開いたときの補完・検証）

これらを別々に書くと食い違いが生じるため、1か所を正として他を導出したい。

## 検討した選択肢

- **JSON Schema を正とし、TS の型を生成する**: スキーマの忠実度は高い。ただし実行時の検証に Ajv 等が別途必要で、
  親の manager に応じた `placement` の検証や参照の解決など、JSON Schema で表せない検証は結局 TS で書くことになる。
- **TS の型を正とし、JSON Schema を生成する**: 型は実行時に存在しないため、実行時の検証が別途必要になる。
- **実行時に検証できるスキーマを TS で書き、型と JSON Schema を導出する**: 重複が最も少ない。ライブラリの候補は次のとおり。
  - Zod 4: 型の導出・JSON Schema 出力（`z.toJSONSchema()`）を備える。利用者・情報量が最大。
  - TypeBox: スキーマ自体が JSON Schema で出力の忠実度が最も高いが、独自の検証が書きにくい。
  - Valibot: Zod と同等の構成でバンドルサイズが最小だが、情報量で劣る。

## 決定

**Zod 4 でスキーマを core に定義し、TS の型と JSON Schema を導出する。**

- 列挙値は TS の `enum` 構文ではなく、文字列リテラルの union（`z.enum([...])`）で表す。選択肢は実行時に取り出してプロパティエディタで使える。
- 検証は2段階とする。
  1. **構造の検証**（Zod スキーマ）: 形・型・列挙値
  2. **意味の検証**（TS の検証関数）: 名前の重複、参照の解決、親の manager と `placement` の対応、ハンドラのシグネチャ、カタログとの照合
- 検証結果（診断）は JSON 上の位置（パス）を持つ。拡張側でパスをファイル上の範囲に変換し、VS Code の問題パネルに表示する。
- JSON Schema はビルド時に生成してリポジトリにコミットし、拡張の `jsonValidation` で `*.tkui.json` に関連付ける。
  生成物がスキーマと食い違っていないかを `pnpm check` で検査する。

## 影響

- core が Zod に依存する（Webview にも同梱される）。
- ウィジェットのクラスごとのオプション補完を JSON Schema に含めるかは、ウィジェットカタログの作成時に判断する。
