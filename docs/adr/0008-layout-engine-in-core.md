# 0008. キャンバス上のレイアウトは Tk のアルゴリズムを TypeScript で再現して計算する

- 状態: 承認
- 日付: 2026-09-24

## 背景

DSL は Tk のジオメトリマネージャ（pack / grid / place）とコンテナの設定（`grid_columnconfigure` の weight、propagate 等）で配置を表す。
デザイナーのキャンバスには、これらに従ったウィジェットの位置とサイズを表示する必要がある。

## 検討した選択肢

- **案a: Tk の pack / grid のアルゴリズムを TS で core に実装する。**
  Tk 環境なしで動き、計算結果を完全に制御できる。ウィジェットの要求サイズは推定値になる。
- **案b: CSS の Grid / Flexbox で近似する。**
  実装は軽いが、pack の空き領域の詰め方、grid の weight による余白配分・縮小時の挙動など、Tk 特有の挙動を再現しきれない。
- **案c: 実際の Tk に配置を計算させ、座標を受け取る。**
  正確だが、利用者の環境に Tk が必要になり、編集のたびにプロセス間通信が発生する。

## 決定

**案a を採用する。** 見た目の最終確認は、将来の実機プレビュー（architecture.md A4）で補う。

### 設計方針

- レイアウトエンジンは core に置く純粋な関数とする。入力: ドキュメントとウィジェットごとの要求サイズ。出力: 各ウィジェットの矩形。
- **要求サイズの計算は外から注入する。** 文字幅の計測などは DOM に依存するため、Webview 側で計測関数を実装して渡す（core は DOM に依存しない方針を守る）。
- pack / grid / place に加え、Notebook のタブ・PanedWindow のペインなど「親が子を配置する」ウィジェットも同じ仕組みで扱う。
- Tk のソース（`tkPack.c` / `tkGrid.c`）の挙動を仕様とし、propagate、weight / uniform / minsize、sticky、ipad / pad を再現する。

### 検証方法

アルゴリズムの正しさと要求サイズの推定の正しさを**分けて**検証する。

1. **アルゴリズムの検証**: 開発時ツールで、同じ DSL を実際の Tk（wish）で表示し、各ウィジェットの `winfo reqwidth/reqheight` と
   実際の配置結果（`winfo x/y/width/height`）を記録する。記録した要求サイズをエンジンに与え、配置結果が Tk と一致することをテストする。
2. **要求サイズの推定**: 推定値と Tk の `winfo reqwidth/reqheight` の差を計測し、許容範囲を定めて改善していく。

## 影響

- core にレイアウトエンジンという大きめのモジュールが加わる。テストデータ（Tk での記録）の作成ツールを `tools/` に置く。
- 要求サイズの推定精度が見た目の再現度を左右する。テーマ（ttk のスタイル・sv_ttk 等）による差異は完全には追えない。
