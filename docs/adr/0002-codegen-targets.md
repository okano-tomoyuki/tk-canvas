# 0002. 生成ターゲットを cpp_tk と Python tkinter の2系統とする

- 状態: 承認
- 日付: 2026-09-24

## 背景

cpp_tk は tkinter と同じ概念・クラス名・オプション名で API を整備している。
この一貫性を活かし、1つの画面定義から複数言語のコードを得られることをデザイナーの強みにしたい。

## 検討した選択肢

- **cpp_tk のみ**: 実装範囲は小さいが、デザイナーの利用者層が cpp_tk 利用者に限られる。
- **cpp_tk + Python tkinter**: 利用者層が広がり、「tkinter で試作 → C++ へ移行」といった使い方もできる。
  一方で、DSL が特定言語に寄らない表現であることが必須になる。

## 決定

cpp_tk (C++) と Python tkinter の両方を正式な生成ターゲットとする。

## 影響

- DSL は **Tk の概念（クラス名・オプション名・ジオメトリマネージャ）で記述**し、言語固有の表現を含めない。
- コード生成は「DSL → 言語非依存の中間表現 → 言語別エミッタ」の2段構成とし、ターゲット追加（Tcl 等）の余地を残す。
- イベントハンドラのシグネチャなど、言語間で差が出る部分は各エミッタの責務として吸収する。
- cpp_tk 側に不足 API が見つかった場合は、cpp_tk 側を整備する選択肢もある。
