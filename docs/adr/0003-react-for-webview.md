# 0003. Webview UI に React を採用する

- 状態: 承認
- 日付: 2026-09-24

## 背景

デザイナーの UI（キャンバス・ツリー・プロパティパネル・パレット）は状態が多く相互に連動する。
旧実装はフレームワークを使わない命令的な DOM / Canvas 操作で、状態の同期が複雑化していた。
本プロジェクトには TypeScript / フロントエンド技術の学習目的もある。

## 検討した選択肢

- **React**: 情報量・エコシステムが最大。学習価値が高い。記述量はやや多い。
- **Svelte**: 記述量が少なく素直。エコシステム・情報量は React に劣る。
- **フレームワークなし**: 依存は最小だが、状態同期を自前で実装することになる（旧実装の課題の再発）。

## 決定

React を採用し、ベストプラクティスに沿った記述を心がける。

## 影響

- 状態管理・Undo/Redo の方式、ビルドツール、UI コンポーネント方針は別途決定する（候補: Zustand / useReducer + Immer、Vite）。
- 「状態は単一のドキュメントモデルに集約し、UI はその射影とする」原則を採る。
  React コンポーネントは表示と操作の発行に専念させ、ドメインロジックは React 非依存のコアパッケージに置く。
